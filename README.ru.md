# DiffMosaic

[English](README.md) | **Русская версия**

**DiffMosaic** — исследовательский инструмент для анализа достаточности
тестирования изменений в Python-проектах. Он не генерирует тесты и не обещает
найти все ошибки. Вместо этого он превращает разницу между двумя ревизиями Git
в проверяемый отчёт и отвечает на более узкий вопрос:

> Для каких изменённых Python-сущностей мало наблюдаемых оснований считать,
> что тесты проверяют новое поведение?

Версия `0.9.0` — небольшой, но воспроизводимый исследовательский прототип. Он
читает локальный Git diff, отделяет производственный код от тестов, сопоставляет
изменённые строки с функциями и классами через AST Python и создаёт
детерминированные отчёты JSON или Markdown. Если разработчик уже подготовил
`coverage.py` JSON, DiffMosaic добавляет к отчёту сведения о покрытии. Анализ и
планирование мутаций не запускают код целевого репозитория.

## Зачем это нужно разработчику

Во время ревью большой pull request обычно отвечает на вопрос «что было
изменено», но хуже отвечает на вопрос «где именно тестовых доказательств пока
не хватает». DiffMosaic помогает построить короткую и объяснимую очередь
проверки:

- показывает изменённые функции, методы и классы;
- отмечает, менялись ли тестовые файлы;
- не выдаёт отсутствие данных о покрытии за отсутствие покрытия;
- предлагает только небольшие мутации в изменённом производственном коде;
- при явном согласии запускает заранее спланированные мутации в изолированном
  Docker-контейнере и записывает результат каждой из них.

Это не «оценка качества программиста» и не предсказатель дефектов. Высокий
приоритет означает только одно: конкретное изменение стоит просмотреть и,
возможно, дополнить тестом.

## Быстрый старт

Требуются Python 3.11+ и Git.

```powershell
git clone https://github.com/FlaksAngel/diffmosaic.git
cd diffmosaic
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[dev]"
python -m pytest
```

Проанализировать две ревизии уже имеющегося локального репозитория:

```powershell
diffmosaic analyze `
  --repo C:\path\to\python-project `
  --base origin/main `
  --head HEAD `
  --format markdown `
  --output report.md
```

Команда ничего не меняет в анализируемом репозитории: использует только
`git diff` и `git show`.

## Типовой процесс работы

```text
Две ревизии Git
       |
       v
analyze -> отчёт об изменённых сущностях
       |
       +-> coverage JSON (необязательно) -> evidence о покрытии
       |
       v
prioritize -> объяснимая очередь ревью
       |
       v
mutate-plan -> кандидаты-мутации только в изменённом коде
       |
       v
mutate-run (явное разрешение + Docker) -> killed / survived / inconclusive
```

Подробный сценарий с командами и интерпретацией отчёта находится в
[руководстве разработчика](docs/ru/guide-developer.md).

## Что происходит при запуске мутаций

`mutate-plan` только читает репозиторий и печатает план. Тесты не запускаются,
файлы с мутантами не создаются. Команда `mutate-run` выполняет потенциально
опасный этап только после `--allow-execution` и только для образа Docker,
которому доверяет сам пользователь. Для каждого запуска она создаёт чистую
временную рабочую копию из `git archive <head>` и использует ограничения:

- сеть выключена;
- корневая файловая система контейнера доступна только для чтения;
- Linux capabilities удалены, включён `no-new-privileges`;
- ограничены CPU, память, число процессов и время;
- временные данные удаляются после завершения.

Ограничения уменьшают риск, но не делают произвольный код безопасным. Запускайте
тесты только тех проектов и образов, которые вам разрешено и безопасно
исполнять. Полный протокол: [английская версия](docs/mutation-execution-protocol.md).

## Исследовательский корпус и текущий результат

В `corpus/pilot-v0.1.json` зафиксированы версии исходных репозиториев,
контейнерные образы, команды и результаты. Там есть один калибровочный пример,
две выполненные внешние наблюдения и исключённые кандидаты с причинами.

В двух выполнимых наблюдениях (Flask и Click) все запланированные мутации были
убиты тестами. Это демонстрирует работоспособность цепочки
«diff → план → изолированный запуск → отчёт», но **не доказывает** полезность
инструмента на Python-проектах в целом: наблюдений пока только два, оба из
одной экосистемы, а набор операторов намеренно мал.

Проверить целостность данных можно без загрузки и исполнения сторонних
проектов:

```powershell
diffmosaic corpus-validate --manifest corpus/pilot-v0.1.json --format markdown
```
